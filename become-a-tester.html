Why we are asking

We test every product with real people before we call it finished. Several of our products are still in development, and some have never run on a real device: no real TV, no real router, no real car, no real tuner. Our own tests can only prove so much. We need people to try Beebo on their own equipment in their own homes and tell us what really happens.

You do not need to be technical for most areas. Every area below says what you need, gives step-by-step instructions and a checklist of things to try, and says how to report back.

If you stay for the whole test and give real feedback, you get a lifetime pass.

Computers and NAS

Windows PC server Available nowBeebo for Windows 0.1.61

What you need

  • A Windows 10 or 11 PC that can stay switched on while you test.
  • A few video files you own (Beebo includes no movies or shows).
  • A phone on the same Wi-Fi, for the phone step.
  • Optional: a metadata-provider key (provider terms apply) for posters (the setup guide shows how, about three minutes).

Step by step: what to do

  1. Download the installer, BeeboEntertainmentSetup.exe (also on the 0.1.58 release page). The Windows setup guide has pictures.
  2. Run it and choose Yes at the administrator prompt. It also adds a Windows Firewall rule named “Beebo Entertainment” for port 47811, so phones on your own network can reach the PC.
  3. On the Get Started screen, create your owner account: a username (at least 3 letters or numbers) and a password (at least 6 characters).
  4. Choose your Movies folder (and TV Shows if you have one), then open the Movies tab. Press Rescan if you add files later.

What to test

  • Run the installer. Write down any warning Windows shows and anything that was unclear.
  • Create your owner account on Get Started. Was every step obvious?
  • Choose your Movies folder. Do your files appear in the Movies tab? Add one more file and press Rescan.
  • Add a metadata-provider key (provider terms apply) (see the setup guide) and rescan. Do posters, cast and descriptions appear? Note any wrong matches.
  • Open a movie and play it on the PC itself. Try skipping forward, subtitles and another audio track.
  • On Get Started, find Connect your phone. Scan the “Scan to connect” QR code with your phone camera. Today it opens your Beebo address in the phone’s browser; it does not sign the app in. Sign in there or in the Android app.
  • If a phone cannot connect, press Can’t connect? Fix it for me (the Connection Doctor). Did it explain the problem in plain words?
  • Close Beebo and restart it, then restart the PC. Is your library still there and does Beebo start again?
  • Play a file your phone or browser cannot play as it is (for example a very large 4K file). Beebo converts video while it plays. Did it start, and did it stutter?

How to report

Include: Your Windows version, the PC (make and model, graphics card if you know it), the Beebo version, and which step went wrong. See the short report template.

Linux PC server BetaAppImage or .deb, 0.1.58

What you need

  • A 64-bit (x86-64) PC running Ubuntu or Debian (for the .deb), or another glibc-based distribution such as Ubuntu 22.04 or newer (for the AppImage).
  • A graphical desktop session. This is the desktop app; a headless server is the Docker area below.
  • For the AppImage: libfuse2 (the package name can differ between distributions).
  • Video files you own, and a phone on the same Wi-Fi.

Step by step: what to do

  1. Download one file from the Linux page or the release page: the .deb (Ubuntu, Debian) or the AppImage (most others). A checksum file is there if you want to verify the download.
  2. .deb: in a terminal in the download folder run sudo apt install ./Beebo-Entertainment-0.1.58-amd64.deb, then start Beebo from the applications menu. AppImage: run chmod +x Beebo-Entertainment-0.1.58-x86_64.AppImage, then run it or double-click it.
  3. Create your owner account and choose your movie and TV folders, as on Windows.
  4. If your PC has a firewall, allow TCP port 47811 on your home network only. For example: sudo ufw allow from 192.168.1.0/24 to any port 47811 proto tcp (change the address range to match your network).

What to test

  • Install and start Beebo. Does it launch? Which install option did you use?
  • Create the owner account and choose your Movies folder. Do your files appear?
  • Add a metadata-provider key and rescan. Do posters appear?
  • Play a movie on the PC. Try skipping forward and subtitles.
  • From a phone or another computer on your Wi-Fi, open http://<this-pc>:47811. Can you sign in and play?
  • Does the tray icon appear on your desktop? (We have not checked this on Linux desktops.)
  • If your desktop has no keyring (GNOME Keyring or KWallet), Beebo keeps saved passwords as plain text in its settings file. Tell us which desktop you use and whether you saw any warning.
  • If you have a graphics card, play something that needs converting and tell us whether conversion seemed to use the graphics card or only the processor (this is untested on real Linux hardware).
  • Close it and start it again. Is your library still there?

How to report

Include: Your distribution and version, your desktop (GNOME, KDE and so on), .deb or AppImage, and whether you have a GPU. See the short report template.

Docker and NAS Available now — BetaPublic image at ghcr.io/swgfan/beebo-server

Installable today. The headless server builds and passes our automated tests, and the image is public on GitHub Container Registry — no sign-in needed to pull it. We have not tested it on any specific NAS model or Raspberry Pi yet, which is exactly what testing this area helps us find out.

What you need

  • A NAS or Linux server that runs Docker, 64-bit x86 or arm64 (Synology, QNAP, Unraid, TrueNAS, a Raspberry Pi 4 or 5, or any Docker host).
  • Some comfort with a terminal or your NAS’s Docker app. This area is for people who already run containers.
  • Folders of video you own, and a phone on the same network.

Step by step

  1. Make a secret key and save it somewhere safe (the data in /config cannot be read without it): openssl rand -hex 32
  2. Run the container:
    docker run -d --name beebo --restart unless-stopped \
  -p 47811:47811 \
  -e BEEBO_UPNP=0 \
  -e BEEBO_SECRET_KEY="<your key>" \
  -v /srv/beebo/config:/config \
  -v /srv/media/movies:/media/movies:ro \
  -v /srv/media/tv:/media/tv:ro \
  -v /srv/media/music:/media/music:ro \
  -v /srv/media/photos:/media/photos:ro \
  ghcr.io/swgfan/beebo-server:0.1.58
    Change the folder paths to your own. Leave off :ro if you want uploads and file clean-up. A wrong setting stops the container with a message listing every problem (exit code 78).
  3. Run docker logs beebo. It prints a first-run address such as https://192.168.1.20:47811/setup and a setup code. Open the address, accept the browser’s certificate warning (Beebo made the certificate itself), enter the code, and choose an owner username and a password of 8 or more characters.
  4. Sign in at https://<server-ip>:47811/. Phones and TVs on your network use http://<server-ip>:47811. The NAS and Docker guide covers permissions (PUID and PGID), graphics cards, host networking and the metadata-provider key.

What to test

  • Start the container. Did it stay running? If it stopped, copy the message it printed.
  • Find the setup address and code in docker logs beebo. Was it clear where to look?
  • Finish first-run setup over https. Did the certificate warning make sense?
  • Do your media folders show up? Rescan and check posters (you need a metadata-provider key, given with BEEBO_TMDB_API_KEY).
  • Open http://<server-ip>:47811 on a phone and play a movie.
  • Check file permissions: is /config writable and are your media readable? Which PUID and PGID did you need?
  • Restart the container. Is everything still there?
  • Try updating by pulling a newer image tag when one is published. Did your data survive?
  • If you have an Intel, AMD or NVIDIA graphics chip, pass it in as the guide describes and tell us whether conversion used it (untested on real graphics hardware).

How to report

Include: Your NAS or server model, its operating system and version, the Docker version, whether it is x86-64 or arm64, and the exact command or compose file you used (hide your secret key). See the short report template.

Can I stop?
Of course, any time — just tell us so we can find someone else. We’d rather know than be short at the end.

Phone speakers (music and movies) BetaNeeds 3 or more phones

Music: Android 1.39 or newer. Movies: Windows 0.1.58, tested only in simulation.

What you need

  • 3 or more phones on the same Wi-Fi, ideally one Android and one iPhone. A fourth phone lets you test joining late.
  • For movies: the Beebo Windows PC, a film with 5.1 sound (any film works; it plays as a stereo pair), and a TV or second screen to show the picture. Guests need no app and no account; they scan a QR code.
  • For music: a host phone with the Android app 1.39 or newer, 2 or 3 guest phones, and a few songs of 2 to 6 minutes in your music library on the Beebo PC.

Step by step: what to do

  1. Movies: open a film’s page, tap Phone speakers, and drag the player window with the QR code onto the TV. On each phone, scan the QR code, type a name, tap Join, then tap Tap to enable audio.
  2. Music: on the host phone queue an album, start a song, and open Campsite then Invite guests. Guests scan the QR code and open Music, then tap Tap to enable audio. On the host, tap Play together.
  3. Keep each guest page open with the screen on. Movies play at normal speed only. Bluetooth speakers add delay, which you can adjust. Phone speakers explains what to expect.

What to test

  • Movies: tap Beep in turn, then Beep together. Does “together” sound like one tick or an echo?
  • Movies: press play. Does dialogue come from the centre phone and effects from the sides? Walk around and listen for echo.
  • Movies: jump ahead and back. How long does the picture wait? Does any phone start late or stay silent?
  • Movies: join a fourth phone mid-film. It should catch up in about 1 to 2 seconds.
  • Movies: close the browser tab on one phone and reopen it. Its sound should move to the TV, then the phone should rejoin by itself.
  • Movies: lock one phone’s screen for 30 seconds, then unlock. Did the sound continue and catch up?
  • Music: on each guest, does “Syncing clocks…” finish within about 3 seconds? Do all phones start within about 2 seconds of each other?
  • Music: pause, play, next and previous from the host. Do all phones follow together?
  • Music: set one guest to Left and one to Right. Does each play only its own side?
  • Music: walk a guest to the edge of the Wi-Fi and back. It should say “Reconnecting…” and rejoin.
  • With a Bluetooth speaker on one phone, use the −10 and +10 ms buttons until the beeps line up. Which value worked?
  • Leave music playing for 20 minutes. Does it keep going?

How to report

Include: Each phone’s make, OS and browser, whether “In sync” went green, and how far off any phone was. See the short report template.

Windows 0.1.58. Never tested on a real tuner.

What you need

  • Change channels and mark one as a favourite.
  • Schedule a one-off recording and a series recording rule.
  • Try to watch or record more channels than your tuner has slots. You should get a polite “busy” message.
  • Add the Recordings folder to the library in Settings and play a finished recording.
  • Restart Beebo. Are your scheduled recordings still there?

Home theater BetaReceiver or soundbar, HDR TV

Never verified on real gear. Beebo does not claim HDR10+, Dolby Vision, Atmos or DTS:X passthrough today.

What you need

  • A 4K HDR TV and, ideally, a receiver or soundbar for the surround checks.
  • A streaming device: Apple TV, Nvidia Shield, Fire TV or Android TV are the ones we name.
  • The Beebo Windows PC and video files you own for each format (HDR10, HDR10+, Dolby Vision, HLG, Atmos, TrueHD, DTS-HD MA, DTS:X). We do not supply sample files.

Step by step: what to do

  1. Put your sample files in your Movies folder and let Beebo scan them.
  2. In Settings, Playback, Home theater, see the options: “Direct play preferred”, “Allow direct stream”, “Allow passthrough”. The Home theater page explains what they do.
  3. Play each file on your TV device and note what your TV and receiver say.

What to test

  • In the desktop Movies table, does the Home theater column show a sensible badge for each file (for example 4K, Dolby Vision, Atmos, 7.1)? Note the file name of any wrong one.
  • Play each sample and write down whether it played.
  • Read your TV’s info banner. What does it say (Dolby Vision, HDR10, HDR10+ or HLG)?
  • Read your receiver’s display. What does it say (Dolby Atmos, DTS:X, TrueHD, Dolby Digital+ or PCM)?
  • Skip forward and back. Do picture and sound stay in step? Any black frame or stutter at the start?
  • Turn passthrough off and play again. The sound should become Dolby Digital Plus with the picture unchanged.
  • Turn on “Always convert” and replay. HDR should become a normal-looking SDR picture.
  • Apple TV: is the picture HDR at all when Beebo copies the file for streaming?
  • Shield or Fire TV: play an MKV directly. If the receiver shows PCM instead of a TrueHD, DTS-HD or Atmos light, check the app’s HDMI passthrough setting and the receiver’s own setting.

How to report

Include: TV make and model, receiver or soundbar make and model, the streaming device, the file format, and exactly what each display said. See the short report template.

Offline check BetaUnplug your router: does home watching still work?

Not yet tried with a real router unplugged or a real phone.

What you need

  • The Beebo Windows PC with a few movies already watched, so posters and details are saved.
  • A phone on the same Wi-Fi with the Beebo app already signed in.
  • Access to your router or modem. Unplug the internet cable (or the modem) and leave the Wi-Fi router on.

Step by step: what to do

  1. Write down the address shown in Get Started (something like 192.168.1.20:47811).
  2. Unplug the internet cable from the router, or switch off the modem. Wait 30 seconds.
  3. Follow the checklist, then plug the cable back in.

What to test

  • Open Beebo on the PC. Does it open at once?
  • Look at the Dashboard chip. It should say “Offline: home viewing still works” within a minute. Press Check now if you do not want to wait.
  • Open Settings and Get Started. Does the Home Wi-Fi note show your number?
  • Open Movies. Do posters and details for titles you already watched still show?
  • Play a movie, skip forward and turn on subtitles.
  • On the phone, close and reopen the Beebo app, choose Home and type the numbers from step 1. Play a movie and a song. (If the app was saved with a name.beebo.tv address, use the numbers instead.)
  • Press Can’t connect? Fix it for me on the PC. It should say “No internet right now, but watching at home works.”
  • Plug the cable back in. Within about a minute the chip should say “Online” with nothing to restart.
  • Note anything that took more than a few seconds or showed an error.

Expected, so not bugs: wide backdrop pictures are not saved locally; titles never looked up before show the file name with no poster; the first page load after the internet drops can take about 3 seconds; away-from-home access, Beebo Relay and BeeboVPN need the internet; the new offline wording is English only.

How to report

Include: What you unplugged, what you saw on each step, and how long anything took. See the short report template.

Accessibility and translations BetaScreen readers; Spanish, French, German, Portuguese (Brazil), Italian

Screen-reader testing with NVDA or Narrator has not been done yet, and no native speaker has reviewed the translations.

What you need

  • Screen-reader and keyboard testers: a Windows PC with the Beebo desktop app and NVDA (free) or Narrator. Run the list with the keyboard alone first, then with the screen reader.
  • Translation checkers: the desktop app and native-level reading of Spanish, French, German, Portuguese (Brazil) or Italian.

Step by step: what to do

  1. Install the Windows app.
  2. Translation checkers: open Settings, Language and pick your language (or leave “Automatic” to follow Windows).
  3. We know some screens have had no accessibility pass yet: sign-in, Upload, Admin, the Dashboard, Users, Live TV, and every Settings panel below the top level. Please report differences from that list, and tell us anything else that fails you.

What to test

  • Keyboard: press Tab from a fresh start. The order should be skip link, sidebar, then the page, with nothing skipped or trapped.
  • Is a focus ring visible everywhere, including the sidebar, poster cards, dialogs and the details page?
  • On Movies, does Tab land on one poster, do the arrow keys move between posters, and does Enter open one? Does Esc on a details page return focus to the same poster?
  • Screen reader: does every icon button and every input announce its purpose, not just “button”?
  • Are page changes, search results and saved settings announced once, not repeated?
  • Open the log-out confirmation, What’s new and the Connection Doctor. Does focus move in, stay inside and return when closed?
  • Set Windows text scaling to 200 percent. Is any text clipped or does anything scroll sideways?
  • Turn on Windows high contrast. Is everything readable and the selected item visible?
  • Translations: switch through the languages. Does English text remain where it should be translated? Is any wording odd, wrong or awkward?
  • Translations: do dates, numbers, plurals (“1 movie”, “2 movies”) and durations look right?

Movie titles and descriptions stay in the language set under Settings, Metadata, and file names are never changed. That is expected, not a bug. The web pages and phone apps are not covered by this pass yet.

How to report

Include: Your screen reader and its version, Windows version, the language you checked, the screen, and the exact wording or behaviour you expected. See the short report template.
