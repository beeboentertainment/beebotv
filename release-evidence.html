What each symbol means

✓ Real testing confirmed

Dark green needs an identified feature, build and device or network test. One passing phone does not validate every platform.

✓ Built · local checks passed

Pale green means the listed local checks passed. A person still needs to check the feature on the stated device. “Tester needed” uses pale green too.

~ Work remains

Yellow means the implementation is incomplete or an identified part is still being built.

× Not offered

Red means that particular capability is not offered. A similar feature may exist, but it must be described separately.

Verification pending means evidence is not yet sufficient for a pass label. It does not mean a test failed. Download availability, settings and billing activation are separate from testing.

Availability is a separate question

The download cards show the published Windows and Android versions and timestamps. Other platform pages describe their own artifacts and tester routes. A source implementation or automated build does not imply store approval or a ready-to-install download for every platform.

The optional AV1 conversion path is off by default and requires a compatible player and available encoder. Stories, casting, billing and other features vary by Android distribution. See the technical guide and the per-platform comparison.

Help turn a local check into a device result

  1. Record your Beebo version, device model, operating-system version and app distribution.
  2. Choose one feature and note its settings, source format and connection route. Use your own or authorized demo files.
  3. Write what you expected, what actually happened, and whether you can repeat it.
  4. Include failures as well as successes. Remove passwords, email addresses, access codes, personal media names and location information from screenshots or logs before sharing.
  5. Submit your result through the tester page. A result is reviewed before a public status changes.
