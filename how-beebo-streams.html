HOW BEEBO HANDLES YOUR OWN VIDEO

Use the lightest path that works.

Beebo uses a just-in-time playback decision: it looks at the file, the player and the selected quality when you press play. It keeps the original file intact and avoids conversion when the current device can play it directly.

Plain English: “just in time” here means Beebo prepares a stream for the device that is watching at that moment. It is not a claim that every movie will start or look the same on every network and device.
01 · FIRST CHOICE

Direct play

If the device understands the file container, video, audio and subtitles, Beebo sends the original file with normal seek support. No FFmpeg conversion process is started.

02 · NEXT LIGHTEST

Compatible stream

If the picture can stay as it is but the delivery container or audio needs adjustment, Beebo repackages or changes only the part that needs work.

03 · WHEN REQUIRED

On-demand conversion

If the player cannot handle the source format or the chosen quality needs a smaller stream, Beebo creates an HLS playback stream for that viewing session.

What the decision checks

File and tracks

Beebo probes the container, video codec, audio tracks, subtitles, resolution, HDR information and duration. It can then explain why a particular path was selected.

The screen that is watching

Beebo keeps capability profiles for different player types. A capable local player can receive the original file; a more limited browser, phone or television can receive a compatible stream instead.

The viewing choice

Quality selection, audio needs, subtitles, remote bandwidth and owner settings influence the plan. The owner can prefer direct play, allow compatible streaming, or deliberately force conversion while testing.

What Beebo’s streaming engine does

  • Direct play: serves the original media through HTTP range requests, so seeking does not require a full file download.
  • Compatible streaming: can remux compatible tracks into HLS segments without re-encoding the video when that is sufficient.
  • Session conversion: uses FFmpeg to create adaptive HLS output only when the decision requires it. The original library file is never overwritten.
  • Encoder checks: tests usable encoders with a real short encode rather than trusting that FFmpeg merely lists an encoder.
  • Fallback order: can prefer available NVIDIA, Intel Quick Sync, AMD, Apple or VAAPI hardware encoders, then fall back to software encoding when necessary.
  • Capacity limits: limits simultaneous conversion and remux jobs so a busy home computer is not overloaded by one person’s playback.
  • Audio choices: can preserve compatible audio, use a supported surround option, or make a stereo mix when the receiving device needs it.
  • HDR handling: the conversion path has HDR tone-mapping support where the selected encoder and device path support it.

Why this approach matters

Processing only what the current playback needs can reduce processor and graphics-card work, reduce start-up work for compatible files, and preserve the original quality whenever direct play is possible. It also means Beebo does not need to pre-convert every title before a household can start using its library.

That is an engineering approach, not a universal performance guarantee. Results depend on the source file, the receiving device, the home computer, available hardware encoding, Wi-Fi or internet conditions, and how many streams run at once.

What is tested, and what still needs broader device testing

Beebo’s direct-play, compatibility-decision and conversion paths are implemented. Real-world validation is still required across more graphics cards, televisions, browsers, mobile devices, operating systems, codecs and home networks. Intel Quick Sync and processor conversion have been exercised on real hardware; other hardware paths need wider independent testing before they are presented as broadly verified.

We do not claim lossless conversion. Direct play preserves the original stream. Any re-encoding can change quality, and Beebo should explain the chosen path rather than hide it.

Questions people ask

Does Beebo always convert a movie?

No. Direct play is the first choice. Beebo converts only where the current device, selected quality or connection requires it.

Does Beebo have to process the whole library before I watch?

No. Beebo scans and understands the library, but playback preparation is chosen when a device starts watching. Optional pre-conversion tools are separate from normal playback.

Is a graphics card required?

No. Beebo can fall back to processor-based conversion. A compatible graphics card can help with some conversion paths, but support depends on the hardware, driver and operating system.

Is this better than every other media server?

Beebo is designed to avoid unnecessary conversion and to show its playback reason clearly. We will compare measured, reproducible results only after independent testing on matching hardware and networks.

Technical comparison guide

Current capability specification

Streaming products often use the same words for different things. This guide separates original-file playback, stream repackaging, and conversion. It also shows whether a capability is included, paid, or an optional upgrade.

$ IncludedUsable without paying that company for the feature. $ Paid serviceRequires that company’s paid plan, unlock, or hosted service. $ Optional upgradeAvailable without it; the paid option adds the stated benefit.

Direct Play

What it is: the original file travels to a device that already supports its container, video, audio, and subtitle tracks. No conversion is needed. Why it matters: original quality with very low server load.

DirectStream / remux

What it is: compatible video is repackaged for the player. Beebo uses fragmented MP4/CMAF HLS for this route. Why it matters: avoids re-encoding compatible video, but it is not identical to Direct Play.

On-demand conversion

What it is: the server makes a compatible stream while it plays. Beebo’s H.264 HLS segments are 4 seconds; it creates segments near the viewing point and removes old session segments. Why it matters: compatibility for a device or connection that cannot play the original.

Capacity needs a condition

A simultaneous-conversion number must state the computer and quality involved. Beebo’s protective starting policy is 1 conversion on a weak PC, 2 on a typical PC, and one more with a working graphics encoder; the owner can adjust it after testing.
