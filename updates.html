Windows 0.1.134

Published Nov 18, 2026, 5:58 PM Eastern (signed by Nicholas Will)

Automated checks: the full Windows desktop test suite (2,102 test files) was run on this release's code just before its release notes were written: 2,058 files passed, 38 were skipped because they need tools or settings this PC does not have, or are switched off on purpose (not run), 3 failed only because of how the run was split and passed when run alone, 2 checks that the What's new list matches the version failed only because the list was added one commit later and passed on the final code, and 1 Shared with you screen check fails the same way on the code this release was built from and is not changed by this release. Windows 0.1.134 (Windows only) has had automated tests and code reviews only; no person has tried its changes or its in-app update yet. Windows only; the phone app and Beebo Auto are separate releases.

  • Podcasts: an episode whose audio address passes through several tracking and redirect links before the real audio file (some shows use six) now plays and downloads instead of failing. This PC now follows up to 10 redirects for episode audio instead of 5, and still checks every step the same way as before. Podcast feeds themselves keep the old limit of 5.
  • Photos: when two backup folders hold photos from the same month, the albums are now named, for example, "October 2026" and "October 2026 · 2". Before, both names added the folder path, which could show the phone backups folder or the phone model. A folder that has its own real name keeps that name.
  • Photos in the browser: an album you open is titled with its short name, never its folder path, and only the owner of this PC receives album folder paths. Other household members no longer do.
  • Browser player, Cast button: "No TV found" now shows only when Google Cast reports that no TV is available. Any other Cast problem (for example a time-out or a session that did not start) now says "Casting could not start. Try again; if it keeps failing, check that the TV and this computer are on the same Wi-Fi." Closing the TV list yourself still shows nothing. When Google's Cast script cannot load and the browser's own casting is used instead, "No TV found" and the automatic report that a file may need converting for casting (sent after about 25 seconds of watching) now happen only after the browser has said no cast device is available, not while it has not answered yet. Google's Cast script still loads only when you tap Cast.
  • Settings search: "volume" now finds the Music section (where music volume levelling is), "Windows" finds the "Keep your server available" section (Beebo's always-on choices), and "space" finds the Playback section, in all 9 app languages. In English, "storage" and "disk" also find Playback, and each other language has its own words for these.
  • Behind the scenes (no change to how the app works): three automated checks were repaired. The offline checks now allow Google's Cast script only after a Cast tap, one player check was given a value the player page now has, and a translation check that ran out of memory now checks one language at a time.
  • Windows only. The phone app and Beebo Auto are separate releases.

  • Live TV: a slow failed retry can no longer replace newer saved Live TV settings, and Set up ignores an older refresh that finishes after a newer one.
  • Music and history: ending a song while it is paused no longer counts the part you did not hear; watched time and storage sizes are never shown below zero; and a damaged time now reads as never instead of "NaN days".
  • Photos: damaged GPS data in a photo no longer becomes a believable but wrong map pin, and a map tile answer that is not an image is refused instead of being kept for a week.
  • Live rooms and phone speakers: a camera change that finishes late can no longer replace your newer camera choice; a failed start with no message now shows a useful one; and a phone microphone answer from before you left the page, a crash or Stop can no longer turn the microphone on afterward.
  • Walkie-talkie: a late Start answer can no longer restart the walkie after you pressed Stop, an older status answer can no longer hide a walkie you just started, and a guest whose sound connection fails is now disconnected instead of looking connected.

A double click can no longer answer the next confirmation box, a folder picker that finishes late can no longer replace the folder you chose after it, and a long layout-pack name no longer stops the chosen layout from working.
  • Moving from another app and add-ons: an empty export file is refused before the wizard says it is ready; a zip archive now stops at its total size limit exactly; and an add-on whose program name differs only in capital letters is accepted.
  • Streaming and connections: a send with no speed limit is no longer slowed down; a person who stops watching no longer lets a converted copy another person is still watching be cleared; a request for a capped video's details no longer reads the video, and a damaged byte range is refused; the movie and TV list addresses refuse write requests; the away-from-home check reports the real outside port your router gave; the status chip shows each home IPv4 address once; device names keep safe non-Latin letters; and a licence renewal check that crashes is retried like an internet outage instead of becoming an app problem.
  • Help and announcements: "Call for help" now says it failed when Windows notifications are not available, instead of saying help was sent, and after Kitchen announcements are turned off an old message can no longer come back.
  • Other fixes: intro detection really checks a file again when you ask for a new scan and no longer waits forever on a stuck converter; turning automatic subtitles off during a scan stops it adding a job, and made subtitles keep each timed line within the 7-second reading limit; the subtitle sweep reports a failed library read instead of an empty result, and a loudness measurement of an older version of a file can no longer replace the newer one; adding the same audiobook folder twice with different capital letters no longer lists it twice; a picture-frame presence check ends even if the PC clock is turned back; long phone upload names are cut without breaking a letter; and Beebo's own logs now also hide IPv6 addresses written in short form.

Know how your phone is connected

The Android connection banner now follows the active connection when its route changes. It identifies Beebo Relay or Cloudflare Relay when that provider can be confirmed. While checking, it says so instead of assuming a direct connection.

A friend’s Wi-Fi or a cellular connection can still connect directly to your home over the internet. The banner reports the actual connection route, not just which network your phone has joined.

Beebo Relay’s encrypted port 443 connection has also been repaired on our server. An enabled relay and a completed away-from-home phone test are now described separately in desktop setup.

Play with friends on their own phones

  1. Update Beebo on the host phone.
  2. Open Other → Games → Play with guests and start your campsite session.
