READ THIS FIRST

A direct connection is required.

What you need

  • A Windows computer running the Remote Desktop test build, with someone present to approve the session.
  • A supported phone browser that can reach that computer through its direct HTTPS address, with a valid, trusted certificate.
  • The server owner’s full sign-in, including any required second factor. Guests and ordinary household profiles cannot request desktop access.
  • A reachable direct peer connection for the screen video. An HTTPS page opening is only the first part of the connection.

What this pilot does not provide

  • No managed Remote Desktop relay, no bring-your-own desktop relay integration, and no STUN/TURN fallback.
  • No promise of access from another network. The usual relayed Beebo media address does not make this desktop feature work.
  • No unattended access, audio sharing, clipboard sync, file transfer or session recording.
  • No control of elevated permission prompts or the secure lock screen.

Start with both devices on the same home network. Direct HTTPS is still required for a normal phone connection. If there is a certificate warning or no working direct address, ask for setup help. Do not bypass certificate warnings or open router ports just to complete this checklist.

YOUR FIRST SESSION

Begin with viewing only.

  1. Prepare your screen. Save your work, close private windows and notifications, and choose a display containing only material you are comfortable sharing. Keep the computer within reach.
  2. Enable local requests. In Beebo Settings → Connection & devices, open Remote Desktop — view your Windows screen and enable requests. This does not start capture.
  3. Open the phone viewer. Use the server’s direct HTTPS address followed by /remote-desktop. Complete the server owner’s sign-in. If sign-in opens the library, open /remote-desktop again, then request view-only access.
  4. Match and approve. Check that the verification code matches on both devices. At the computer, approve the request, select exactly one display, then press Start sharing this display.
  5. Check stopping before control. Confirm the selected screen is visible, then stop sharing from the computer. The phone must stop receiving updates. Start a fresh approved session if you want to test again.

Keyboard and mouse control can affect ordinary applications and files. The selected display limits what you see; it is not an application sandbox. Keyboard input goes to whichever application currently has focus. Test control only in an empty, disposable document after a separate local approval.

PUBLIC TESTER CHECKLIST

Tell us what actually happened.

For each item, report Pass, Fail, Not tested or Blocked. Record the exact build and devices used. One successful device or connection does not prove every device will work.

1 / Setup and sign-in

  • The installed Windows version matches the test build.
  • Beebo opens and your normal library remains accessible.
  • Remote Desktop starts off; enabling requests does not start capture.
  • The direct HTTPS page opens without a certificate warning.
  • Owner sign-in and any required second factor work; a guest or ordinary profile cannot request desktop access.

2 / View and stop

  • Declining a request leaves the screen unshared.
  • The code matches, display choice is explicit, and capture waits for the Start sharing click.
  • Only the selected display is shown; orientation and scaling are usable.
  • The visible sharing controls remain available at the computer.
  • Stop sharing ends the video. A new session needs fresh approval.

3 / Optional control

  • A separate local approval is required before any input reaches the computer.
  • A pointer click and a short test sentence work in an empty, disposable document.
  • Return to view only stops further input while viewing can continue.
  • Switching away from the phone page releases control.
  • Ending the session leaves no key or mouse button held down.

4 / Interruptions and usability

  • After saving your work, lock or sleep the computer: sharing stops and does not silently resume.
  • Close the sharing window or briefly interrupt the connection: sharing ends and needs a new approval.
  • Text, controls and focus remain usable with larger text and keyboard navigation.
  • Report freezes, heat, CPU load, battery impact, picture quality and delay as observations—not guaranteed performance.
  • Record another-network attempts separately, including blocked connections.
