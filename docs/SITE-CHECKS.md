# Running the website checks

Install this checkout's dependencies with `npm ci`, then run `npm test`,
`npm run check:evidence` and `node scripts/check-site-shell.mjs`.

The shared-shell checker validates canonical markers, links and anchors, cache
keys, duplicate chrome and generator idempotence on pages using the shared shell.
It also requires existing bodies, body attributes, standalone exceptions and the
five protected data files to match a baseline. The default is the checkout's
`origin/main`, resolved once to a commit and printed in the result. Fetch before
starting a lane; use `--base <exact SHA>` to pin a review or migration comparison.
A missing/invalid base fails. New canonical pages still receive every shell
check, and the result explicitly reports their missing baseline comparison.
New or changed standalone exceptions fail preservation and need their separate
generator/content review.

The October 2026 snapshot exported by `scripts/site-shell.mjs` remains the
historical migration/audit reference. It predates later pages and releases, so it
is not a valid default preservation baseline for ongoing site checks. For the
old comparison, pass that SHA explicitly with `--base`.

`ai-test-results.html`, `test-builds.html` and `what-we-checked.html` were added
after the shell migration with standalone evidence layouts. Feature-detail pages
are generated by `tools/build-feature-pages.mjs`; check them using
`npm run check:evidence`. These pages are explicit shell exceptions, still checked
for preservation against the chosen base. Dependencies under `node_modules/` and
local checker snapshots under the ignored `site-check/` are tooling, outside the
website inventory. Unknown public HTML pages are not automatically exempted.

Feature generation comparisons accept either LF or Windows CRLF line endings.
They do not ignore other whitespace or content changes, and `--check` never
rewrites a page.
